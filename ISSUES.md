## Step 0 — Environment

- **[Step 0] `pdftotext` not installed** — poppler is absent on this Mac. Extracted `docs/assignment.pdf` with `pypdf` inside the project virtualenv instead (allowed by the build prompt).
- **[Step 0] System Python is 3.9** — `/usr/bin/python3` is 3.9.6. Built the virtualenv (`.venv/`) with Homebrew Python 3.14.2 for current `openai`/`playwright` wheels.
- **[Step 0] `prompt.md` git-ignored** — the agent orchestration prompt sits in the project root and mentions the endpoint host by name. It is not a deliverable, so it is excluded via `.gitignore` to keep the host name out of the tracked tree.
- **[Step 0] Metadata kept in predictions files** — decision: carry `verified_purchase`, `helpful_vote`, `timestamp`, `asin`, `parent_asin`, and `images_count` (length of `images`) into every `predictions.jsonl` row, for slicing errors later (e.g., are unverified reviews harder?). Dropped `user_id` (a reviewer identifier with no analytic use here, and no reason to republish it) and the raw `images` URLs (bulky). None of these fields is ever passed to the model; `build_messages` accepts only `title` and `text`.
- **[Step 0] Inclusion rule** *(addition)* — rows whose `text` is empty after stripping whitespace are excluded from every run. 49 of 152,410 rows fail it (by rating: 1★ 18, 2★ 3, 3★ 1, 4★ 1, 5★ 26). The assignment says "first 100 rows"; `batch_100` is the first 100 `review_id`s that pass the rule, a small deliberate deviation.
- **[Step 0] Model is a "thinking" model; first call returned no answer** — `cyankiwi/Qwen3.6-35B-A3B-AWQ-4bit` (the only model `/v1/models` offers) spent all 200 `max_tokens` on a hidden `reasoning` field and returned `content: null`, `finish_reason: length`. Passing `extra_body={"chat_template_kwargs": {"enable_thinking": false}}` (a vLLM chat-template switch) made it answer `LABEL=POSITIVE` directly with 0 reasoning tokens in 0.5 s. Decision: every classification call disables thinking, so `max_tokens` can stay small as the parse policy requires; the setting is recorded in each `run_meta.json`. `temperature=0` was accepted without error.
- **[Step 0] Imbalance confirmed at the source** — full file: 5★ 84.1%, 4★ 4.4%, 3★ 2.1%, 2★ 1.2%, 1★ 8.1% (`runs/rating_distribution.json`). Binary truth (≥4 positive) is therefore ~88.5% POSITIVE across the file, so a model that always says POSITIVE scores ~88% before doing anything useful.

## Step 1 — Structured prompt, binary

- **[Step 1] Indirect rating leak through auto-generated titles** — while reading spot-check candidates, titles such as "Five Stars", "Three Stars", "One Star" turned up. Counting over the 152,361 included rows: 31,868 titles (20.9%) are exactly "<One–Five> Star(s)" (1★ 684, 2★ 139, 3★ 428, 4★ 1,653, 5★ 28,964), and the number equals the rating in 31,838 of them. They are Amazon's auto-filled titles, i.e. the rating itself. Passing them would break "the model never sees the rating". Fix: `build_messages` blanks a title (or a text — 13 texts are only such a phrase) that fully matches `^(one|two|three|four|five) stars?$`; the prompt says either field may be empty. The stored `title`/`text` in predictions stay original; `verify_leak.py` rebuilds the messages and asserts no such phrase was sent. Done before any run used `sentiment_v1.txt`, so the prompt was still editable.
- **[Step 1] Parser self-test caught a code-fence bug** — the first fence-stripping regex (`^`+[a-zA-Z]*`) treated `LABEL` in a single-backtick reply `` `LABEL=POSITIVE` `` as a fence language tag and deleted it, so a valid answer would have been counted FAIL. Fixed: a line that is only a fence (```` ``` ```` / ```` ```text ````) is skipped; other lines have backticks trimmed from both ends. `src/test_classify.py` covers both forms.
- **[Step 1] `openai` 3.x uses `httpx2`** — the self-test's `import httpx` failed; the SDK now depends on `httpx2`. Switched the import.
- **[Step 1] `verify_leak.py` crashed on a relative extra-file path** — `Path.relative_to` needs absolute paths; it also left a temp file in `reviews/`. Now resolves the path and writes the temp file under git-ignored `cache/`; the stray file was deleted.
- **[Step 1] Spot check 10/10** — 5 clearly positive and 5 clearly negative reviews picked by reading only (review_ids 1043, 1113, 1197, 1218, 1232 / 1453, 1624, 2473, 3637, 4511, all outside `batch_100`); the model's labels matched reading on all 10, and the ratings revealed afterward (five 5★, five 1★) agreed too. Caveat: picked for being obvious, so this proves the plumbing, not accuracy. Evidence: `reviews/step1_spotcheck.txt`, `.json`.
- **[Step 1] Residual path, not closed: customers who mention stars in their own words** — 909 included texts say things like "5 stars" or "one star because…" inside longer text. That is the customer's review content, which the assignment tells us to classify, so it is left intact and disclosed rather than rewritten. `verify_leak.py` counts these per run.
